# Complete-Type Reindexing Along Variable Maps

## Intent

Introduce a generic contravariant reindexing operation on arbitrary complete types so callers can
restrict a type along a variable map without first realizing it in a model or exposing formula
relabeling and constant-expansion bookkeeping.

The public operation should have the shape

```lean
def CompleteType.reindex
    (f : α → β) (p : T.CompleteType β) :
    T.CompleteType α
```

and support semantic naturality, functorial laws, variance-sensitive injectivity and surjectivity,
and the Stone-space behavior needed by downstream complete-type transports.

The current project already has concise lemmas for projecting and relabelling *realized* types. The
purpose of this plan is not to replace those proofs merely for brevity; it is to expose the same
contravariant structure directly on arbitrary complete types so later code does not have to pass
through a realizing model when no realization is otherwise needed.

## Facts / Observations

### Current code already handles realized-type projection

`ModelTheory/Types.lean` contains
`CompleteType.typeOf_comp_eq_of_typeOf_eq`, which says equality of realized complete types is
preserved by precomposition with a variable map. Its `Sum.inl` and `Sum.inr` specializations give
`typeOf_left_of_typeOf_sum_eq` and `typeOf_right_of_typeOf_sum_eq`.

`ModelTheory/IsolatedTypes.lean` also already proves `CompleteType.isIsolated_typeOf_left` with a
short semantic argument: existentially project an isolating formula with `Formula.existsRight`, use
`Formula.realize_existsRight`, and project equality of joint tuple types with
`typeOf_left_of_typeOf_sum_eq`.

Therefore the older motivation of eliminating a long hand-written projection proof is obsolete.
Generic reindexing should be justified by callers that need to act on arbitrary complete types or on
the Stone space itself, not by churn in the existing realized-type projection theorem.

### Variance

Reindexing is contravariant. A function

```lean
f : α → β
```

should induce

```lean
CompleteType.reindex f : T.CompleteType β → T.CompleteType α
```

by restricting a `β`-indexed type to formulas whose variables are relabeled along `f`.

Consequently:

- if `f` is injective, `CompleteType.reindex f` is expected to be surjective;
- if `f` is surjective, `CompleteType.reindex f` is expected to be injective;
- an injection `α ↪ β` does not canonically extend an `α`-type to a `β`-type;
- an actual embedding in the covariant direction requires extra data, such as a retraction or a
  chosen section of the induced restriction map.

For `Sum.inl : α ↪ α ⊕ β`, the natural map is therefore

```lean
T.CompleteType (α ⊕ β) → T.CompleteType α.
```

### Existing semantic infrastructure

Mathlib exposes `CompleteType.nonempty_iff`, realization of every complete type in a model, and the
Stone topology generated by `Theory.typesWith`. Locally, `Formula.realize_relabel` and the
realized-type projection lemmas above already encode the semantic naturality that the generic
operation should package.

Before implementation, search the current Mathlib dependency again for an upstream complete-type
reindexing or restriction API. Do not assume that the API surface seen when this plan was first
drafted is still current.

### Related but distinct transports

`ModelTheory/TypeSpaceHomeomorphism.lean` transports complete types along *language equivalences*.
That construction changes the language while keeping the variable type fixed. The operation in this
plan keeps the language and theory fixed while changing the variable index contravariantly. Reuse
shared proof ideas where useful, but do not conflate the two interfaces.

A sibling `StabilityTheory` repository has also used restriction APIs for types. It may be consulted
for design comparison, but this repository must not acquire a filesystem or Lake dependency on it.

## Design

### Core interface

Introduce the main operation in the `CompleteType` namespace:

```lean
def CompleteType.reindex
    (f : α → β) (p : T.CompleteType β) :
    T.CompleteType α
```

The implementation should stay behind this interface. Callers should not need to know how the
underlying maximal theory, a realizing model, or temporary constant structures are constructed.

The fundamental membership theorem should be stated for formulas:

```lean
@[simp]
theorem CompleteType.formula_mem_reindex
    (f : α → β) (p : T.CompleteType β) (φ : L.Formula α) :
    Formula.equivSentence φ ∈ p.reindex f ↔
      Formula.equivSentence (φ.relabel f) ∈ p
```

If the implementation naturally produces a sentence-level transport operation, keep it private
unless a concrete second caller benefits from exposing it. Formula-level membership is the intended
public test surface.

### Semantic naturality

Prove compatibility with realized types:

```lean
@[simp]
theorem CompleteType.reindex_typeOf
    {M : Type*} [L.Structure M] [Nonempty M] [M ⊨ T]
    (f : α → β) (v : β → M) :
    (T.typeOf v).reindex f = T.typeOf (v ∘ f)
```

This theorem should reduce to `Formula.realize_relabel` and should make the generic operation agree
with the behavior already proved by `typeOf_comp_eq_of_typeOf_eq`.

Add the functorial laws:

```lean
@[simp]
theorem CompleteType.reindex_id
    (p : T.CompleteType α) :
    p.reindex id = p

@[simp]
theorem CompleteType.reindex_comp
    (p : T.CompleteType β) (f : α → β) (g : γ → α) :
    (p.reindex f).reindex g = p.reindex (f ∘ g)
```

Prefer proving these through `formula_mem_reindex` and extensionality rather than unfolding the
implementation.

### Injectivity and surjectivity

Prove the variance-sensitive mapping properties:

```lean
theorem CompleteType.reindex_surjective_of_injective
    {f : α → β} (hf : Function.Injective f) :
    Function.Surjective (CompleteType.reindex (T := T) f)

theorem CompleteType.reindex_injective_of_surjective
    {f : α → β} (hf : Function.Surjective f) :
    Function.Injective (CompleteType.reindex (T := T) f)
```

A semantic proof of surjectivity may realize the target type in a nonempty model and extend its
assignment along the injection. The unsatisfiable-theory case should fall out uniformly from the
empty complete-type spaces rather than forcing an unnecessary completeness assumption.

For an equivalence `e : α ≃ β`, package reindexing as an equivalence only if this removes repeated
inverse calculations:

```lean
def CompleteType.reindexEquiv (e : α ≃ β) :
    T.CompleteType β ≃ T.CompleteType α
```

Do not add both a specialized `restrictVars` interface and generic `reindex` without a concrete
readability benefit.

### Stone topology and isolation

Prove continuity when downstream Stone-space arguments need the generic map:

```lean
theorem CompleteType.continuous_reindex (f : α → β) :
    Continuous (CompleteType.reindex (T := T) f)
```

For injective `f`, investigate whether the useful reusable statement is openness of reindexing or
only preservation of isolated points:

```lean
theorem CompleteType.IsIsolated.reindex
    {f : α → β} {p : T.CompleteType β}
    (hp : p.IsIsolated) (hf : Function.Injective f) :
    (p.reindex f).IsIsolated
```

If an open-map theorem is introduced, the image of a basic open should be represented by
existentially quantifying variables outside the image of `f`, keeping finite support internal rather
than requiring a global complement type in the public API.

Do not refactor the existing `isIsolated_typeOf_left` merely to force it through this abstraction.
Its current `existsRight` proof is already short and semantic. Change it only if the final generic
API makes the theorem materially clearer or removes duplication needed elsewhere.

## Specs / Constraints

- Do not assume that `T` is complete; reindexing is an operation on complete types over an arbitrary
  theory.
- Do not add a canonical covariant extension of complete types along an injection.
- Do not expose realizing-model, witness-extension, or temporary-structure bookkeeping in the
  public interface.
- Keep the public abstraction generic in the variable map.
- Preserve the concise existing realized-type projection API; make it a corollary of generic
  reindexing only when that reduces duplication without making proofs less transparent.
- Keep variable reindexing distinct from language-equivalence transport and parameter-language
  transport.
- Do not import or depend directly on the sibling `StabilityTheory` repository.
- Search the current Mathlib dependency before adding a local replacement or committing to theorem
  names from this plan.

## Implementation / Verification

### Implementation order

1. Start from the current project mainline and search the current Mathlib dependency for an upstream
   complete-type reindexing/restriction operation and relevant topology lemmas.
2. Recheck the current downstream callers and keep the scope driven by arbitrary-complete-type use,
   not by the already-simplified `isIsolated_typeOf_left` proof.
3. Define `CompleteType.reindex` and prove `formula_mem_reindex`.
4. Prove `reindex_typeOf`, `reindex_id`, and `reindex_comp`.
5. Prove the variance-sensitive injectivity and surjectivity results.
6. Add continuity and isolation/open-map results only to the extent required by the active callers;
   avoid building a larger Stone-space API speculatively.
7. Revisit existing realized-type projection lemmas only if the generic API provides a clear
   simplification without obscuring their semantic proofs.

Blueprint work is outside this plan by default. Do not inspect for synchronization work, modify
`blueprint/`, or run blueprint validation unless the user explicitly authorizes blueprint work. If
such work is authorized, follow the repository's blueprint instructions for both edits and
validation instead of treating blueprint synchronization as an automatic completion step here.

### Verification

```bash

```

If modules or imports change, additionally run:

```bash
lake exe mk_all --check
```

If the implementation changes only documentation, use the repository CI/validation applicable to
the changed files. Blueprint validation remains out of scope unless blueprint work was explicitly
authorized.

### Completion criteria

- `CompleteType.reindex` exists with a formula-level membership theorem and semantic naturality for
  `typeOf`.
- Identity and composition laws are available without callers unfolding the implementation.
- The variance-sensitive injectivity and surjectivity results are proved for arbitrary theories.
- Any added topology/isolation API is justified by a current caller and is verified with the same
  public abstraction rather than exposing implementation bookkeeping.
- Existing concise realized-type projection proofs are not replaced with more complicated generic
  machinery merely to demonstrate the new API.
- Required repository validation passes, with blueprint work performed only when explicitly
  authorized.
